# Arbor v0.2 协议修正与最小化重构计划

> 状态：**COMPLETE — v0.2 已收口；release breadth 与 deferred budget 经 owner waiver**
> 日期：2026-09-11
> 输入任务书：[Arbor v0.2 架构审查与重构任务书](../../Arbor%20v0.2%20架构审查与重构任务书.md)
> 基线：Arbor v0.1 已验收实现
> 原则：先修真实协议缺陷；能在现有文件内说清的，不新增抽象或目录。

---

## 1. Review 结论

任务书判断出的四个高优先级问题都真实存在：

1. residual-only 轮次可能在 validation 执行前错误 STOP；
2. scope 仍按 changed location 归属，会漏掉 change-induced、untouched manifestation；
3. reviewer 同时输出 `severity`、`blocking`、`discipline`，产生重复 policy state；
4. no-progress 把“旧 blocker 已解决、发现同数量新 blocker”误算成 stagnation。

这些问题应在 v0.2 修复。任务书提出的其他抽象只保留解决当前问题所需的最小形态。

Arbor 的核心仍是：

> 冻结目标 change，让两个 fresh、read-only lens 审查同一完整材料，由唯一 writer
> 归并根因、修复、执行项目验证并有界收敛的 Agent Review Protocol。

不创建通用 workflow engine、runtime object、状态数据库或第三 reviewer。

## 2. 反思与消融结果

上一版方案本身出现了任务书警告的倾向：把“把语义说清白”扩张成新增多个文件和协议对象。以下设计取消。

### 2.1 取消的设计

| 取消项 | 原因 | 替代 |
|---|---|---|
| 新建 `review-packet.md` | ReviewPacket 没有第二种实现；独立文件会与 scope/prompt contract 重复 | 在现有 `reviewer-prompt-contract.md` 中命名一个 `Review materialization` 段 |
| 新建 `invariants.md` 与 INV-01…编号体系 | 给七条规则分配 ID 不会提升 Agent 行为，反而污染 prompts 并增加维护映射 | 现有 prompt contract 保持唯一规范文本；checker 检查必要 projection 的关键条款 |
| 新建 `runtime-adapters.md` | 当前只有两个短 runtime 分支；现有 prompt contract 已有 runtime table | 从 core SKILL 删除具体派发说明，仍放在现有 runtime table |
| ReviewPacket 的 `packet_id`、`validation.state`、`state_revision` | reviewer 不需要知道 orchestrator validation 状态；这会把 policy 泄漏进输入 | validation freshness 只保留在 convergence contract 的内部状态说明 |
| ReviewPacket 的 `excluded.previous_findings` 字段 | “不携带 prior findings”是边界规则，不是应传给 reviewer 的数据字段 | prompt contract 明确禁止，验收时离线检查 |
| 产品合同强制 packet hash | Agent 不需要计算 hash，且 hash 不是协议行为 | acceptance extractor 离线比较同轮公共材料；hash 只是证据实现细节 |
| 独立 normalized finding YAML 协议 | Arbor 没有持久化 consumer；强制第二套序列化会制造新 API | finding-schema 中用一张 normalize/policy 表说明 orchestrator 内部状态 |
| 10 个 case 各建一份 Markdown | 只有一个 plugin，十份小文件会造成文档散落 | 一个 `evals/dual-review-loop/README.md` 集中定义 E01–E10 |
| 新建 behavioral eval runner/engine | 容易复制一套 convergence 状态机，测试最终只证明“第二个实现” | fixture builder + evidence checker；真实 outcome 仍由 release agent run 验证 |
| 新增 `docs/architecture.md` | 当前 plugin README 足以承载一页逻辑架构 | 更新现有 root/plugin README |
| manifest generator | 一个 plugin、两个短 manifest，没有生成系统的收益 | deterministic parity check |
| 9 个阶段、10 个建议提交 | 拆得过细会产生大量跨文件不可运行中间态 | 收敛为 5 个阶段、5 个原子提交 |

### 2.2 保留但降级为轻量概念

#### Review materialization

保留 “Review materialization” 这个轻量名称，但不把它做成对象、文件或 framework。规范只定义两个 reviewer 同轮必须收到的公共材料：

```yaml
review_materialization:
  scope:
    type: working-tree | branch | commit-range | files
    baseline: <commit-or-null>
    paths: [<path>]
  project_instructions:
    sources: [AGENTS.md, <other>]
  target_change:
    full_current_materialization: <baseline→current diff + changed files
      + one-hop interaction inventory>
```

规则：

- 同轮两个 reviewer 的公共材料相同；
- lens rubric 和 output schema 不属于公共材料，可以不同；
- 下一轮重新物化 current state，但 frozen baseline 不变；
- 不携带 prior findings、global F-id 或上一轮修复叙事。

#### Canonical reviewer boundary

不建立 invariant registry。`reviewer-prompt-contract.md` 的 isolation template 继续是唯一规范文本。reviewer skills 和 Claude agents 是必要 projection；checker 只检查以下语义必须存在：

- read-only；
- fresh context；
- same full materialization；
- no prior findings；
- no nested agents；
- findings returned to parent；
- main agent is the only writer。

#### Runtime boundary

不建立 Adapter 类型或目录。Core SKILL 只写“按 runtime adaptation section 并行派发两个 lens”；现有 prompt contract 的 Codex/Claude table 继续承载具体派发与 enforcement 差异。

### 2.3 明确不做

- Generic Convergence Engine；
- server、database、MCP orchestration；
- persistent finding ledger；
- 第三 reviewer 或第三 runtime 扩展点；
- manifest/code generator；
- prompt/invariant generator；
- 为历史 v0.1 transcript 建迁移 parser；
- 为了示意图机械移动现有目录。

## 3. 审查证据与优先级

### P0

无。当前没有证据显示 v0.1 会造成安全漏洞、数据损坏或不可恢复外部写入。

### P1-01：Residual-only validation 顺序错误

当前 `dual-review-loop/SKILL.md` 的顺序是：

```text
if convergence gate met AND required validation green:
    run final required validation if not yet run
...
if none actionable:
    STOP
```

validation 为 UNKNOWN 时，第一条件不成立；若 reviewer 只有 non-blocking residual，又没有 finding 可修，流程可能落入 STOP。

目标顺序：

```text
derive gate blockers
if gate blockers == 0:
    ensure validation is current
    PASS if validation passes
    otherwise classify the validation failure
```

validation 结果必须对应当前 tree。main agent 任意写入后，之前的 PASS 立即失效；这只是 convergence contract 内部规则，不进入 reviewer 输入。

### P1-02：Scope ownership 过窄

`review-scope.md` 和两个 reviewer skills 都把 finding 限定在 added/modified code。它会漏掉：

```text
changed provider contract
→ untouched caller becomes invalid
→ crash manifests in untouched file
```

v0.2 原则：

> A finding is in scope iff the target change causes or materially worsens it.

untouched code 可以是 manifestation、caller/callee 或 compatibility evidence。与 change 无因果关系的 pre-existing issue 仍然 out of scope。

### P1-03：Reviewer schema 暴露 gate policy

raw finding 同时包含 severity、blocking；structure 再包含 discipline，并允许 `taste` 作为 schema value。由此能表达 protocol 不允许的状态。

v0.2：

- correctness reviewer 输出 `severity: P0 | P1 | P2 | P3`；
- structure reviewer 输出 `structural_class: regression | improvement`；
- 两者都不输出 `blocking`；
- taste 不进入 findings，只能进入聚合 residual risk；
- orchestrator 根据固定 policy table 派生是否阻断，不新增持久化 schema。

默认 policy：

| Reviewer classification | Default | Strict |
|---|---|---|
| correctness P0/P1 | BLOCK | BLOCK |
| correctness P2 | RESIDUAL | BLOCK |
| correctness P3 | RESIDUAL | RESIDUAL |
| structure regression | BLOCK | BLOCK |
| structure improvement | RESIDUAL | BLOCK |
| taste | no finding | no finding |

直接危及正确性的缺陷必须标为 P1，不保留“P2 但 blocking”的例外。若 classification 明显与证据冲突，orchestrator 不静默升降级：先做一次 evidence resolution；仍不确定则 STOP conflict。

### P1-04：No-progress 混淆 stagnation 与 churn

当前合同将相同数量的新 blocker 替换旧 blocker 视为 no progress。v0.2 改为语义集合：

```text
persistent = previous ∩ current
resolved   = previous - current
new        = current - previous
```

规则：

- round 1 只建 baseline；
- 只有 persistent blockers 连续无语义改善，且 validation 未改善，才累计 no-progress；
- 有 resolved blocker 或 persistent blocker 有实质改善时 counter 清零；
- new blocker 只记录为 churn，不触发 no-progress；
- max_rounds 继续限制持续发现新 blocker 的循环。

不新增 churn guard 或 churn state machine。

### P1-05：验收证据尚未形成 regression gate

v0.1 有高质量 transcript 和 fixture builder，但没有仓库命令检查 manifest parity、schema 禁止字段、公共 materialization 一致性和关键 outcome evidence。

v0.2 只新增一个 checker、一个测试文件、一个集中 eval 说明和一个 CI workflow，不创建 eval framework。

### P2-01：Runtime 细节在 core 中重复

orchestrator SKILL 和 prompt contract 都描述 Codex/Claude 派发。删除 SKILL 中的平台细节，保留 prompt contract 的现有 runtime table。

### P2-02：Final output 过度限制

当前要求两个模板之一且 “nothing longer”，会与用户显式要求详细说明冲突。

v0.2 保留 exactly one canonical PASS/STOPPED block；用户显式要求或 STOP 决策需要时，可以在 block 外附加说明，但不得产生第二个 outcome。

### P2-03：Distribution metadata 依赖人工比对

两个 manifests 当前一致，但 version/name/license/repository/source path 无自动 parity gate。新增 checker 足够，不做 generator。

## 4. 最小目标架构

```text
Distribution
  manifests / marketplace / version / license
        │
Runtime projection
  existing prompt-contract runtime table + Claude agents
        │
Core Review Protocol
  scope / materialization / finding policy / validation / convergence
        │
Correctness Lens              Structure Lens
        └──────── same review materialization ────────┘
                              │
                    normalize / dedupe
                              │
                    single-writer fix
                              │
                    project validation
                              │
                    fresh full re-review
                              │
                         PASS / STOP

Repository QA（不进入 plugin runtime context）
  one checker + one test module + one eval runbook + CI
```

没有独立 ReviewPacket layer、Invariant layer、Adapter layer 或 Evals framework。它们只是现有协议/仓库 QA 中的职责名称。

## 6. 最小协议改法

### 6.1 Review materialization 放回现有 prompt contract

只定义 reviewer 真正需要的输入：

```yaml
review_materialization:
  scope:
    type: working-tree | branch | commit-range | files
    baseline: <commit-or-null>
    paths: [<path>]
  project_instructions:
    sources: [AGENTS.md, <other>]
  target_change:
    full_current_materialization: <baseline→current diff + changed files
      + one-hop interaction inventory>
```

不包含 validation result、round history、finding history、policy profile 或 packet identity。

### 6.2 Causality-based finding location

保留现有 `location`，只增加一个字符串因果说明，不引入 origin/manifestation 对象树：

```yaml
location:
  file: untouched/handler.py
  symbol: HandleUser
causal_link: changed/service.py:GetUser changed nullability and made this caller invalid
```

当 location 本身就是 changed code 时，`causal_link` 可省略；当 location untouched 时必须提供。pre-existing unrelated issue 不得用该字段强行包装进 scope。

### 6.3 Reviewer schema 只保留观察与分类

不强制创建第二套 normalized YAML。orchestrator 在 session 内维护：

```text
F-id
root cause
sources
derived severity
gate effect
lifecycle
```

这是算法状态，不是新的文件格式或公共 API。

### 6.4 Validation freshness 不进入 reviewer context

convergence contract 只需一句可执行规则：

> A validation result is current only if no repository write has occurred since that command completed.

因此不需要 revision object、tree digest 或 validation record class。验收 transcript 记录命令、结果及其后是否有写入即可。

### 6.5 Semantic consistency 不做生成

checker 只验证确定性事实：

- manifests 可解析；
- name/version/license/repository parity；
- marketplace source path 存在；
- SKILL frontmatter 和 agent preload 名称有效；
- prompt contract 的七条 boundary 在必需 projections 中存在；
- reviewer envelope 不含 `blocking:`；
- structure finding enum 不含 taste；
- output reason 与 convergence reason 一致；
- eval evidence 文件和字段齐全。

checker 不理解自然语言 policy，不生成 prompt，不实现 convergence。

## 8. 集中 Regression Eval 矩阵

全部写在一个 `evals/dual-review-loop/README.md`：

| Case | 必须证明 |
|---|---|
| E01 Clean | round 1 clean + current validation → PASS |
| E02 Correctness blocker | fix → validation → fresh full review |
| E03 Structural regression | regression blocks；improvement/taste 不阻断 |
| E04 Dedupe | 同 root cause 一个 F-id；不同 root cause 不合并 |
| E05 Residual-only | 无 gate blocker + residual → validation → PASS |
| E06 Cross-boundary | changed cause + untouched manifestation 仍 in scope |
| E07 Progress | persistent stagnation 触发；resolved+new churn 不触发 |
| E08 Oscillation | A→B→A 按 precedence STOP |
| E09 Conflict | 一次 evidence resolution；仍冲突则 STOP |
| E10 Validation failure | change-caused 可修；不可归因/外部阻断则 BLOCKED |

每个 case 只要求：

- fixture 或 synthetic history；
- expected outcome；
- required evidence checklist；
- Codex 与 Claude 的 release result link。

不创建通用 evaluator。deterministic checker 只验证 evidence 完整性和静态合同，不替 Agent 判定语义结果。

## 10. 风险与约束

| 风险 | 缓解 |
|---|---|
